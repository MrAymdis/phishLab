# 企业微信通道钓鱼演练设计方案（v2）

> 状态：设计稿（待评审确认后实施）。适用版本：当前主线（一期已交付，二期部分功能在建）。
> v2 相对 v1 的核心变化：引入**网页授权 OAuth 双轨溯源模型**——追踪令牌负责演练归因，
> OAuth 负责真实身份识别，事件模型新增 `wecom_visitor_user_id`，支持"传播链"分析。

## 1. 背景与目标

平台目前通道为邮件（SMTP），二期规划 EWS/SMS。企业微信是自有员工钓鱼演练的高频场景：
员工日常以企微沟通，用企微应用消息投放模拟钓鱼，仿真度和到达率均优于邮件。

目标：
1. 通过**自建应用消息 API** 向指定员工（userid 定向）投递演练消息；
2. 完整行为追踪闭环：点击 → 落地页 → 提交 → 即时教育 → 画像/报表；
3. **双轨溯源**：token 归因"哪场演练、发给谁"，OAuth 归因"实际是谁点开/提交"，解锁传播链分析；
4. 全部合规红线落地（敏感配置加密、域名隔离、授权强制、仅自有员工、载荷门控）。

## 2. 通路选型

| 通路 | 定向个人 | 行为追踪 | 审批成本 | 结论 |
|---|---|---|---|---|
| 自建应用消息 API（`message/send`） | ✅ 按 userid | ✅ 卡片链接 → H5 | 企业管理员授权安装自建应用 | **主方案** |
| 群机器人 Webhook | ❌ 只能发群 | ❌ 无法定位个人 | 低 | 仅作演练公告辅助（P2） |
| 企业客服/会话存档 | ❌ | ❌ | 高 | 不采用 |

**"伪装发件人"= 应用自身**：客户管理员在企微管理后台自定义应用名称与头像
（如"IT 服务中心""HR 通知"），对应邮件场景的 `sender_profile` 显示名伪装。
平台侧只保存应用名（展示用），不控制头像。

## 3. 双轨溯源模型（v2 核心）

### 3.1 两个身份，各司其职

| 身份 | 来源 | 回答的问题 |
|---|---|---|
| `user_id`（收件人/目标） | token → campaign_target | "这条消息**发给谁**、属于哪场演练" |
| `wecom_visitor_user_id`（实际访问人） | OAuth `snsapi_base` 静默授权 | "**实际**是谁点开/提交的" |

- 企业微信**无已读回执**，`open` 事件不可得，`click` 即最高频入口事件；
- `click` 动作发生在落地页加载**之前**，OAuth 若只在落地页做，无法给 click 补身份 →
  **OAuth 前置到追踪层**（§5.2），click/submit 两类事件均带双身份；
- 非企微环境（转发到普通浏览器/个人微信打开）OAuth 静默失败 → `wecom_visitor_user_id` 为空，
  链路降级为纯 token 归因，不影响主流程。

### 3.2 传播链定义（衍生分析，无需新表）

```
wecom_visitor_user_id IS NOT NULL AND wecom_visitor_user_id != user_id
  → "该消息被目标员工转发/传播，实际中招者是 wecom_visitor"
```
报表能力：转发传播链（A 转发 → B 中招）、跨演练重复中招人识别（同一 wecom_visitor 多场出现）。

## 4. 端到端时序

```
① worker 投递：message/send（textcard 卡片，url = TRACK_BASE_URL/t/{token}）
② 员工点卡片按钮 → 企微内置浏览器打开追踪域
③ GET /t/{token}：记录 click（此时 wecom_visitor 未知）→ 302 到 /t/{token}/identify
④ GET /t/{token}/identify：302 到企微 OAuth authorize（snsapi_base，静默）
⑤ 企微回调 landing/track 的 /wx/cb?code=...&state={token}
    → code 换 userid → 写 Redis 映射 wecom_visitor:{token} → userid（TTL 2h，与演练会话对齐）
    → 302 回落地页 /p/{slug}?t={token}
⑥ 落地页渲染（企微风仿真实页）；用户提交表单
⑦ submit 事件：后端读 Redis wecom_visitor:{token} 增强 wecom_visitor_user_id → 进 Redis Stream
⑧ track_stream 消费者落库（click 事件由消费者按同一映射补 wecom_visitor_user_id）
⑨ 中招后即时教育 + risk_recalc 重算画像（口径不变：中招=submit+attach_run）
```

> click 事件先于 OAuth 回调进 Stream，消费者落库时从 Redis 映射补 wecom_visitor_user_id；
> 若映射已过期（用户挂机超 2h 才提交），click/submit 仅 token 归因，wecom_visitor 留空——可接受。

## 5. 数据模型设计（Alembic 迁移）

### 5.1 send_channel 扩列（沿用宽表模式，同 sms_*/ews_* 风格）

```sql
ALTER TABLE send_channel ADD COLUMN wecom_corp_id    VARCHAR(64)  NULL,
                        ADD COLUMN wecom_agent_id   VARCHAR(32)  NULL,
                        ADD COLUMN wecom_secret_enc VARBINARY(512) NULL,  -- 红线2 AES-GCM
                        ADD COLUMN wecom_app_name   VARCHAR(64)  NULL;   -- 显示名（展示用）
-- type 取值 'smtp/ews/sms' 扩为 'smtp/ews/sms/wecom'（String(8) 无需改列）
```

### 5.2 emp_user 增企业微信身份

```sql
ALTER TABLE emp_user ADD COLUMN wecom_userid VARCHAR(64) NULL;
CREATE UNIQUE INDEX uk_emp_wecom_userid ON emp_user(wecom_userid);
```
- 来源：组织同步（§8）/ CSV 导入 / 手工编辑；
- 目标展开规则：**无 wecom_userid 的员工跳过该通道并返回"未匹配名单"告警**，不静默丢弃。

### 5.3 wecom_template（新表）

```sql
CREATE TABLE wecom_template (
  id          BIGINT PRIMARY KEY AUTO_INCREMENT,
  name        VARCHAR(128) NOT NULL,
  msg_type    VARCHAR(16)  NOT NULL COMMENT 'textcard/news/text/markdown/file',
  title       VARCHAR(128) NULL,               -- 卡片标题
  description VARCHAR(512) NULL,               -- 卡片摘要
  btn_text    VARCHAR(16)  NOT NULL DEFAULT '查看详情',
  url_mode    VARCHAR(16)  NOT NULL DEFAULT 'track' COMMENT 'track=追踪链接/custom=自定义',
  custom_url  VARCHAR(255) NULL,
  media_id    VARCHAR(64)  NULL,               -- file 消息上传素材（红线6 门控，默认不开放）
  status      VARCHAR(16)  NOT NULL DEFAULT 'draft' COMMENT 'draft/approved/discarded',
  created_by  BIGINT, created_at DATETIME, updated_at DATETIME
);
```
- 复用 `ai_draft` 草稿审核流（AI 产出一律先草稿、人工确认后入库，硬约束）；
- 落地页复用 `landing_page` 表，新增"企业微信登录"仿真模板场景（静态 UI，不含真实企微 OAuth 流程）。

### 5.4 track_event 增访问人身份

```sql
ALTER TABLE track_event ADD COLUMN wecom_visitor_user_id BIGINT NULL COMMENT 'OAuth溯源的实际访问人（可空=非企微环境/降级）';
CREATE INDEX idx_track_wecom_visitor ON track_event(wecom_visitor_user_id);
```
- 事件类型**不新增**（identify 不是业务事件，仅作 click/submit 的增强列）；
- 去重口径不变：token+event_type+时间窗。

### 5.5 频控配额

复用 `SendQuotaUsage`（channel 模块已有），记录 wecom 通道日发送量、失败数与配额水位。

## 6. 模块设计（按模块分包归位）

```
app/modules/channel/     # 通道配置 CRUD（type=wecom 分支）+ 密钥加解密 + 掩码回显
                         # service: get_wecom_access_token()（Redis 缓存 7200s，提前 300s 刷新，
                         #   分布式锁防雪崩）+ send_wecom_message()（httpx async 客户端）
app/modules/campaign/    # 目标展开 wecom 分支（userid 解析、无 userid 告警）、授权勾选项扩展
app/modules/template/    # wecom_template CRUD + ai_draft 审核流接入
app/modules/tracking/    # /t/{token} 现有链路不变；新增 /wx/cb OAuth 回调端点（track 服务）
                         # code→userid 兑换 + Redis wecom_visitor:{token} 映射（TTL 2h）
app/modules/org/         # 组织同步 source=wecom：通讯录 API 只读拉取 → userid/部门落库
app/modules/analytics/   # 传播链报表（wecom_visitor != target 聚合）、通道维度扩展
worker/tasks/wecom_sender.py   # 投递任务：批次调度、频控退避、errcode 映射、幂等重试
worker/tasks/track_stream.py   # 消费者扩展：click/submit 落库时按 wecom_visitor:{token} 补 wecom_visitor_user_id
```

### 6.1 投递引擎（worker）

```python
@celery_app.task(bind=True, max_retries=3, retry_backoff=True)
def wecom_send(self, target_id: int):
    # 幂等：uk_campaign_batch 批次粒度；单目标重发仅允许 send_status in (pending, failed)
    resp = await send_wecom_message(channel, emp.wecom_userid, template, token)
    errcode = resp["errcode"]
    # 0        → sent（企微无已读回执，sent 即终态；delivered 不适用）
    # 40014    → token 失效：强制刷新后重试
    # 45009/45024 → 频控：指数退避（60s 起，×2，封顶 30min）
    # 60111    → userid 不存在 → bounced（同步标记该 target 并告警）
    # 60011/60020 → 权限/应用不可用 → failed（告警人工介入，不无限重试）
```

- 批量发送按通道配额调速（默认串行批次，规模大时 worker 副本扩展）；
- `test_send`：向发起管理员自己的 `wecom_userid` 试发（管理员账号需绑定员工档案，否则提示先建员工档案）。

### 6.2 OAuth 回调端点（track 服务，可信域名内）

```
GET /wx/cb?code=xxx&state={token}
 1) 校验 state 格式与 /t/{token} click 记录存在（防伪造回调打流量）
 2) code → getuserinfo（snsapi_base，静默）→ userid
 3) SET wecom_visitor:{token} = userid EX 7200
 4) 302 → LANDING_BASE_URL/p/{slug}?t={token}（slug 从 token 关联 campaign 解析）
```

> **只用 `snsapi_base`**：静默、无授权弹窗（不破坏仿真）。
> 禁用 `snsapi_privateinfo`（需成员点同意，会暴露演练且索取手机号邮箱越界）。

### 6.3 事件口径

| 事件 | 企微可采集 | 口径 |
|---|---|---|
| open | ❌ 无已读回执 | 不采集；点击率口径 = click 数 / 成功发送数 |
| click | ✅ /t/{token} | 卡片按钮点击；wecom_visitor 由 Redis 映射补 |
| submit | ✅ 落地页表单 | 中招核心事件；wecom_visitor 增强 |
| report | ✅（P2 举报机器人） | 复用现有 |
| attach_run | ❌ 默认关闭 | 文件消息载荷属红线 6，旗舰授权门控后才有 |
| bounce | ✅ errcode 60111 | userid 不存在 |

画像/风险重算**零改动**：click→链接点击+8、submit→中招+1 等口径沿用 `risk_recalc`。

## 8. 组织同步（source=wecom）

- 通讯录只读接口：`department/list`（树）、`user/list`（成员：userid/name/mobile/department/email）；
- 匹配策略：**userid 优先** → email 次之 → 均不中按配置决定"创建或跳过"（默认跳过并出清单）；
- 部门树：企微部门 id 映射 `emp_dept`（名称路径重建，`path` 按现有 id 规则）；
- 手机号走红线 2：AES-GCM 加密入库。

## 9. 安全合规红线映射

| 红线 | 企微落点 |
|---|---|
| 2 敏感配置加密 | `wecom_secret` AES-GCM 入库、API 掩码回显；access_token 只进 Redis |
| 3 域名隔离 | 卡片 URL/落地页仍在独立演练域 `p.*`/追踪域 `t.*`，不与主平台同域同 IP |
| 4 授权强制 | 创建企微演练强制勾选：① 已获企业书面授权 ② 应用可信域名已配置 ③ 仅针对本企业成员 ④ **已向员工披露静默身份识别（OAuth）** |
| 6 载荷门控 | file 消息（恶意文档）默认关闭，旗舰授权才解锁 |
| 8 仅自有员工 | 目标仅限 `wecom_userid` 匹配的本企业 `emp_user`；通讯录同步只读 |

**文案合规**：模拟消息禁用"微信安全中心/官方通知"等冒充官方字样，一律以客户内部部门名义
（IT 部/HR），与邮件 DMARC 约束同理；模板审核流做关键词拦截。

## 10. 报表扩展

- 演练报表通道维度加 `wecom`；点击率 = click/sent（**不展示 open 口径**，避免误导）；
- 传播链报表：`wecom_visitor != target` 的事件聚合 → 传播人榜、被传播中招榜；
- `stat_daily` 聚合：wecom 事件按 `dim_type=channel` 归口（`_aggregate_day` 扩展）。

## 12. 风险与边界

| 风险 | 说明 |
|---|---|
| 无已读回执 | open 不可得，点击率口径需向客户说明 |
| 可信域名池 | 每个演练域名都须配入应用"网页授权及 JS-SDK 可信域名"；域名池轮换成本高 |
| 微信插件环境 | 企业开微信插件后员工在个人微信收消息；网页授权在微信内可用但需真实验证，P0 验收必测项 |
| 频控 | 通讯录/消息接口有企业级配额，大批量需调速发送（>1000 人分批延时） |
| OAuth 时延 | 静默授权 1-2 次 302（约几百 ms），click 到落地页首屏略有延迟，可接受 |
| 授权书 | 需客户法务确认 OAuth 静默识别的披露条款（红线 4 延伸） |

## 13. 测试要点

- 单元：errcode 映射、token 缓存刷新、频控退避、幂等重发；
- 集成：卡片点击 → click 落库带 wecom_visitor → 落地页提交 → submit 双身份 → 画像重算；
- 仿真：企微内置浏览器/个人微信/普通浏览器三环境验证 OAuth 降级与降级链路；
- 合规：无 userid 员工跳过告警、授权勾选缺失拦截、敏感字段掩码回显。
