# 举报插件部署说明（Outlook Web Add-in / Web 邮箱扩展）

举报插件让员工在邮件客户端内一键把可疑邮件提交到平台举报中心（`POST /report/v1/mail`，X-Api-Key 鉴权）。
两个客户端共用同一套上报接口与配置：**API Key 不随安装包分发**，由管理员在平台导出「引导配置 JSON」逐客户交付。

## 1. 组件与资产

| 资产 | 地址 | 说明 |
|---|---|---|
| Outlook manifest | `/report/v1/plugin/outlook/manifest.xml?base=<平台地址>` | 服务端动态生成：SourceLocation/图标注入客户可达的绝对 URL（`{BASE}` 模板替换） |
| Outlook 任务窗格 | `/report/v1/plugin/outlook/taskpane.html` 等 | 公开托管（加载项加载必须无鉴权） |
| Web 邮箱扩展包 | `/report/v1/plugin/webmail.zip` | MV3 扩展，运行时从 `app/modules/report/plugin_assets/webmail/` 打包 |
| 引导配置 | `GET /api/v1/mail-reports/plugin-config/export`（JWT + `report:classify` 权限） | 含 `serverUrl` + 明文 API Key + `allowedDomains`，下载行为记审计（红线 2 取证口径） |

- `base` 参数由前端传 `location.origin`：平台前有反代（vite/nginx）改写 Host，服务端 `request.base_url` 对客户不可达。
- 资产静态托管带路径穿越防护（目标必须在 `plugin_assets/` 目录内）。

## 2. 管理员操作（邮件举报 → 举报插件管理）

1. **插件 API 配置**：生成/重生成 API Key（加密存储仅回显掩码）、配置允许域名列表、Webhook、自动分类。
2. **下载「引导配置 JSON」**（API 配置区按钮）——含明文 Key，仅交付给部署插件的管理员。
3. 分发 manifest.xml / webmail.zip / 引导配置 JSON 给员工（或由 IT 统一部署）。

### 域名白名单（fail-closed）

配置了 `allowedDomains` 后，举报人邮箱不在列表内 → 上报被拒（`10001`）；未配置则放行。
Key 泄漏的爆炸半径被限制在允许域名内。

## 3. Outlook 客户端安装（Web Add-in，非 MSI/VSTO）

1. 下载 `manifest.xml` 与引导配置 JSON。
2. **单人**：Outlook → 文件 → 管理加载项 → 我的加载项 → 添加自定义加载项 → 选择 manifest.xml。
   **企业批量**：Microsoft 365 管理中心 → 集成应用程序 → 上传自定义应用（集中部署）。
3. 打开任意邮件，功能区出现「安全举报」组；点「举报可疑邮件」打开任务窗格。
4. 任务窗格首次使用导入引导配置 JSON（存 roamingSettings，随账号漫游）。

支持 Outlook 2016+（Win/Mac）与 Microsoft 365。任务窗格 JS 按 ES5 + XHR 编写，兼容 Outlook 2016 的 IE11 webview。
邮件头（`getAllInternetHeadersAsync`）需 ReadWriteMailbox 权限，权限不足时自动跳过（不影响上报）。
新版 Microsoft 365（Mailbox 1.14+）会自动随举报上传整封邮件 EML（ReadItem 权限即可），用于全文归档与溯源（见 §5）。

## 4. Web 邮箱扩展安装（Chrome/Edge/Firefox，MV3）

1. 下载 `phishlab-webmail-plugin.zip` 并解压。
2. Chrome/Edge：`chrome://extensions` 开开发者模式 → 加载已解压的扩展程序；Firefox：`about:debugging` → 临时载入附加组件。
3. 点工具栏图标 → 粘贴引导配置 JSON → 保存。
4. 打开 Web 邮箱任意邮件，页面右下角出现悬浮「举报」按钮 → 弹层确认（举报人邮箱必填、主题预填当前页标题）→ 提交。

- 请求由扩展 **service worker** 发起（`host_permissions` 覆盖平台域名），豁免邮箱页面 CORS 限制。
- UI 全部走 Shadow DOM，与邮箱页面样式隔离。
- Web 页面取不到邮件 Message-ID，精确匹配演练属二期能力（当前按发件人/主题人工研判）。

## 5. 上报接口契约

```
POST /report/v1/mail
X-Api-Key: plr_...
{ "channel": "outlook_plugin|webmail", "reporter_email": "...", "message_id": "...",
  "from_addr": "...", "subject": "...", "headers": "...",
  "eml_base64": "…" }
```

| code | 含义 |
|---|---|
| 0 | 入库成功 |
| 40101 | Key 无效或未生成 |
| 10001 | 举报人邮箱域名不在白名单 |
| 41002 | 该 `message_id` 已举报过（重复上报拦截） |

### EML 全文归档（Outlook 新版 Microsoft 365）

Outlook 任务窗格通过 `getAsFileAsync`（Mailbox 1.14+，ReadItem 权限即可）把整封邮件 EML 以 base64 随举报上报；服务端落盘 `static/report_eml/{id}.eml` 并从归档解析：

- **邮件头回填**：`headers` 缺失时从 EML 提取（含 From/To/Date/Message-ID 等），溯源分析不再依赖 `getAllInternetHeadersAsync` 的 ReadWriteMailbox 权限；
- **管理端预览**：`GET /api/v1/mail-reports/{id}/preview`（JWT + 数据权限）返回元信息/正文（截断 20KB）/附件清单（名称+大小）；
- **原件下载**：`GET /api/v1/mail-reports/{id}/eml`（`message/rfc822` 附件）。

约束与降级：

| 场景 | 行为 |
|---|---|
| EML 解码后 > 8MB（base64 约 10.7MB，客户端已留余量） | 跳过归档，仅元数据上报 |
| 非法 base64 / 不像邮件的内容 | 跳过归档，上报不阻断 |
| 客户端显式上报的 `headers` | 优先保留，EML 不回填覆盖 |
| Web 邮箱 / 旧版 Outlook | 无 EML 能力，纯元数据模式（详情页显示对应占位提示） |

## 6. 故障排查

| 症状 | 排查 |
|---|---|
| Outlook 功能区无按钮 | manifest 校验失败——用 base 重新下载；确认客户端版本 ≥2016 |
| 任务窗格空白 | 平台域名从员工终端不可达；查 manifest 里 SourceLocation 是否注入正确 base |
| 上报 40101 | Key 已重生成/未导入：重新下载引导配置导入 |
| 上报 10001 | 举报人邮箱域名未加入白名单，或引导配置过期（白名单变更后需重新导出） |
| 上报 41002 | 同邮件重复举报，正常拦截 |
| Web 邮箱无悬浮按钮 | 扩展未加载或未配置；刷新页面重试 |

## 7. 开发与测试

- 后端资产与路由：`app/modules/report/service.py`（`build_outlook_manifest` / `build_webmail_zip`）、`router.py`（`/report/v1/plugin/*`）。
- 图标由 PIL 生成（品牌蓝 #378ADD + 白色叹号），替换图标后重跑生成脚本。
- 测试：`server/tests/test_plugin_pack.py`（配置导出/域名校验/重复拦截/manifest 注入/zip 打包/路径穿越/EML 归档——测试内 `monkeypatch` 重定向 `static_dir` 到临时目录，绝不写生产静态目录）。
- webmail.zip 每次请求实时打包，改 `plugin_assets/webmail/` 无需重启服务。
